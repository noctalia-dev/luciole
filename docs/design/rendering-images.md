# Rendering and images

## Shared and application-owned code

`lib/` is a normal local copy of Noctalia's reusable library. Do not patch it in Luciole. Port generic fixes upstream before copying reviewed updates back; do not introduce a sibling include path, shell service or second renderer.

[library_setup.cpp](../../src/app/library_setup.cpp) supplies application identity, explicit asset roots, palette, UI strings and the Luciole image provider. Luciole selects its canonical environment/install asset root before library initialization. An invalid explicit root fails rather than silently searching elsewhere.

Luciole owns decoration negotiation, clipboard/drop transport, cursor fallback, browser composition and selection contours. Common widgets use the actual shared Button, Stepper, Select, Toggle, ScrollView and virtual-grid controls. A file-manager preference binding belongs here, while a generic widget correction belongs upstream.

The compositor's fractional-scale preference belongs to one Wayland surface. Output updates refresh the output scale seed without clearing that preference; subsequent preferred-scale events replace it. Destroying the Wayland surface clears the preference before the object can create another surface.

## UI phases

Preserve PrepareFrame → Update → Layout → Render.

- Update applies prepared state and publishes model/UI changes.
- Layout measures, mutates scene structure, binds visible cells and chooses physical image sizes.
- Render only paints prepared state. It performs no layout, traversal, filesystem I/O or decoding.

Callbacks schedule the required phase. They do not synchronously rebuild a scene from an arbitrary worker or input callback. Virtual cells release work when hidden, retired or rebound; bounded pooling must not retain every file in a large directory.

## Icon theme updates

Luciole owns icon selection and monitoring in `src/system/icon_resolver.*` and `icon_theme_poll_source.*`. Desktop GSettings selects the theme when its schema is available; GTK settings.ini provides a fallback. The main-loop watcher observes `changed::icon-theme`, reads the key after connecting, and debounces selection changes alongside existing artwork file watches. Accepted changes invalidate the application icon cache and rebind browser artwork. GSettings objects are optional when the schema is absent; observer teardown disconnects callbacks. The `icon-theme` suite uses private schemas/settings and artwork to exercise selection, fallback, live changes and file replacement.

Size-aware lookup first chooses artwork within the directory's declared Fixed, Threshold or Scalable range, then its closest nominal size. SVG beats PNG only at an otherwise equal size score. When no range matches, the existing preference for gentle downscaling over enlargement remains; the first theme with a matching name still owns the result. The size-free lookup retains its scalable/large-first order. Scoring skips filesystem checks for candidates that cannot improve the result. Selection and decoding remain on the existing workers, with physical-pixel cache keys and unchanged invalidation.

This respects the size-specific artwork described by the [Icon Theme Specification](https://specifications.freedesktop.org/icon-theme/latest/) and compared through native [GTK icon lookup](https://docs.gtk.org/gtk4/method.IconTheme.lookup_icon.html). Papirus makes the difference visible: its [96-pixel Places directory](https://github.com/PapirusDevelopmentTeam/papirus-icon-theme/blob/master/Papirus/96x96/places) links to the 48-pixel drawings, while its [128-pixel directory](https://github.com/PapirusDevelopmentTeam/papirus-icon-theme/blob/master/Papirus/128x128/places) links to the 64-pixel drawings. Selecting the latter at 96 pixels introduces fractional geometry and different padding despite both files being vectors. Lookup therefore considers size before format, ahead of physical-size rasterization.

Resolver instances retain a shared immutable search plan and per-instance result/missing caches. A published plan owns a cached immutable watch-path snapshot; callers may keep old snapshots safely across theme/content generations. Temporary hash sets deduplicate search/watch paths while ordered vectors retain first-match theme, inheritance and size precedence. Building a plan stats each search directory once: lookups skip directories that did not exist, and their modification times form the content signature, a 64-bit FNV-1a hash like the plan signature. A directory that appears later changes a watched ancestor and rebuilds the plan. Generation changes clear local results and acquire the new plan. IconThemePollSource schedules initial discovery, content/signature checks and watch construction through serial cancellable GTask work. The main context keeps the optional GSettings subscription, reads its key after connecting, receives inotify events and coalesces pending content/metadata flags with a 100 ms debounce. Its 60 s fallback check runs only while the watch set is missing or incomplete; a complete set wakes nothing while idle.

Watch replacement keeps the old set active while the worker constructs a new set. Named ancestor watches are installed first, including parents of linked or missing directories. A post-registration content validation covers edits before coverage existed: when icons were already looked up, the content generation is invalidated; when none were, comparing the rebuilt plan's signatures is enough and an unchanged theme keeps its generation. Changed paths trigger another construction pass. Completion drains the old queue before replacement and the new queue afterward, preserving further edits as pending work. Dropping old watch sets schedules their kernel-watch removal on a worker too. Closed sources disconnect settings, cancel work and reject late completions through weak lifetime ownership; teardown never joins a worker on the UI thread. Preserve actual filesystem path semantics around symlinks and `..`.

This removes synchronous watcher work from startup and normal dispatch, with extra validation/allocation costs. Full coverage and refresh completion can take longer, and measured CPU/PSS rise. Resolver plans remain immutable and shared, and image work still belongs to existing icon workers. This does not change file-listing storage or move scene/GPU mutation onto a worker.

## Thumbnail and preview pipeline

One application-wide [ThumbnailService](../../src/thumbnails/thumbnail_service.h) owns bounded generation requests, revisions, priority and cancellation for both browsing thumbnails and preview images: one memory budget, one decoder pool sized to a quarter of the CPUs (two to six helpers). Preview requests run first, then visible cells. Work nobody holds is cancelled. Released images stay resident until they go unseen for five minutes (thirty seconds for previews), so returning to a folder or scrolling back does not wait for the disk or a decoder; a held image counts as seen. A 256 MiB budget, charged each image's real decoded size, is only a safety cap that evicts the least recently used. Purpose is part of an image's identity, since previews accept no smaller foreign thumbnail and take clean video frames. [PreviewService](../../src/thumbnails/preview_service.h) requests preview content through it; the service's owner forwards change notifications to each page's preview. Their generation policy, freedesktop disk store and FFmpeg/Poppler providers remain Luciole-owned.

Thumbnail policy defaults to Local. It skips paths whose filesystem may go over a network, using the folder listing's network filesystem types. FUSE counts as network only without a disk device number (`major(st_dev) == 0`), so ntfs-3g on a disk stays local while rclone, sshfs and gocryptfs are skipped; a path whose filesystem cannot be read is skipped as well. All permits generation for regular files with an accessible filesystem path, including mounted network shares, without treating a remote/unknown filesystem flag as a generation ban. Locations with no filesystem path remain shared-cache-only; no whole-source remote download is introduced. Use the same held descriptor, identity/revision checks, cancellation and bounded worker/provider queue as for local files. Image/PDF sources retain the configured encoded-byte cap; seekable video/audio do not inherit that cap and remain subject to helper CPU, wall-time, memory, pixel and output bounds. Cache publication and source-change checks are unchanged.

Raster images use the [GdkPixbuf/Glycin adapter](../../src/imaging/pixbuf_image_decoder.cpp). Decoding/provider processes run outside Render with bounded input, pixels, memory and time. Helper memory is capped with `RLIMIT_DATA`, not `RLIMIT_AS`: Glycin's thread pools and allocator arenas reserve far more address space than they touch, and an address-space cap made large images fail at random. [thumbnail_worker.cpp](../../src/thumbnails/thumbnail_worker.cpp) and [provider_process.cpp](../../src/thumbnails/provider_process.cpp) enforce the helper protocol; [thumbnail_store.cpp](../../src/thumbnails/thumbnail_store.cpp) validates shared PNG cache entries. Dependencies and installed loader coverage belong in [PACKAGING.md](../../PACKAGING.md).

Shared-cache PNG metadata accepts `tEXt`, `zTXt` and `iTXt`, including Qt-compressed URI fields. Decompression is bounded to 128 KiB per value and 256 KiB total text, with the existing CRC, chunk, pixel and file-size checks retained. Browsing can reuse a valid smaller third-party cache class when a larger one is absent; high-resolution previews still require their requested size. Imported cached pixels and any baked-in decorations are left intact.

The shared cache has no Luciole-side index. A write publishes through a private temporary file renamed over the URI's spec path, replacing any older thumbnail for that URI, whichever application wrote it. After each batch (completions gathered for 250 ms, up to 64), one scan of the four size folders sums regular, user-owned, spec-named PNGs and removes the oldest by modification time until the configured byte budget holds. Clear Cache removes only PNGs whose Software label is Luciole.

Video generation first probes duration and the file's embedded cover images (attached-picture streams). When it has any, the best cover is used as is, without the filmstrip decoration, for both browsing and preview requests: Matroska cover names win (`cover_land`, `small_cover_land`, `cover`, `small_cover`), then the picture with the most pixels. A cover that fails to decode falls through to frame sampling. Otherwise generation samples the keyframe nearest 10% (keyframe-only decoding avoids decoding every frame since the previous keyframe), and tries another position near one third when the first sample is almost entirely black. Short/unknown-duration clips and failed seeks retain a first-frame fallback, and genuinely dark clips remain valid. Cover and sample attempts share the existing eight-second video request budget; source descriptors and helper resource/protocol limits remain. `X-Luciole::VideoVersion` distinguishes the current cover-first sampling from Luciole’s older cache entries; only those old Luciole results need regeneration, while other thumbnailers’ cache images remain reusable.

[FileIcon](../../src/ui/browser/file_icon.h) holds shared-library prepared-image leases. Immutable RGBA and source/revision/size identities enter [SharedTextureCache](../../lib/render/core/shared_texture_cache.h). Dispatch owns GPU upload and switching; identical prepared requests share residency within an EGL group. Do not reinstate per-cell texture uploads or a second Luciole GPU cache.

Layout requests physical pixels, including display scale. Grid thumbnails cannot replace the larger preview request. Keep an already ready image visible until a higher-resolution replacement uploads, preserve aspect ratio, and retain source dimensions separately from decoded/output dimensions. Source revisions must invalidate same-size edits without flushing unrelated images.

Preview and Properties share [asynchronous metadata](../../src/thumbnails/preview_metadata.h). The preview presents essential content facts; Properties can expose technical and permission information. Selecting a single folder starts the shared [folder totals service](../../src/fs/folder_totals.h) once for that selection: the preview shows its size and its file and folder counts, a new selection supersedes the running walk, and a running walk never marks the page busy. Properties keeps the explicit inspection card with its Stop button and detailed partial-result notes.

The list view Size column walks bound folder rows through the same service family: [BrowserController](../../src/browser/browser_controller.h) runs at most two walks for the rows its enabled list adapter binds, refuses network filesystems on the worker with the same probe family as thumbnail reads, stays on each row's own filesystem so a nested mount is never traversed, and publishes each terminal result into a per-entry cache that also absorbs refusals, dropping entries when the listing republishes changed facts or retires the id. Rows show the finished size; “≥” marks partial results; refused network rows keep the cell blank; bounded progress never repaints rows and a walk never marks the page busy. Drive removal cancels its walks and drops cached sizes under the removed root alongside the thumbnail reads. Miller columns, grid captions, selection totals and Properties keep their existing behavior.

Native symlink metadata retains the no-follow query for the link's own facts and adds the literal stored target and filesystem-resolved absolute target on that same worker. Resolution preserves symlink/`..` ordering, reports missing/inaccessible/looping targets and never enumerates the target. The link's inode and change revision are rechecked before publishing; cancellation and superseded-request guards remain. Resolution is observational, with no target lease or live target monitoring. Opening links uses a separate following type query; native `stat` errors and a provider's unresolved symlink type prevent default-handler dispatch. Permission and transfer services keep their existing no-follow policies.

This follows [Nautilus 49's single-link Properties field](https://raw.githubusercontent.com/GNOME/nautilus/gnome-49/src/nautilus-properties-window.c), inspected as a primary-source comparison. Luciole additionally separates the stored target from the final native path. [GIO documents](https://docs.gtk.org/gio/method.File.query_info.html) that a following query can still return the link itself when its target does not exist; opening must handle that result explicitly. No live comparison or broader remote-target metadata support is claimed.

## Shared video decoration

Browsing requests send their selected video frame through the system `ffmpegthumbnailer -f` filter, matching its standard desktop thumbnailer entry. The input is a private PNG re-encoded from validated pixels, passed by descriptor, rather than the original media. This preserves Luciole’s representative-frame selection and source pixel/protocol limits. Decoration runs on the existing worker, with one CPU, at most two seconds and the remainder of the same eight-second video budget. Validate the resulting PNG and require unchanged dimensions. Missing/failed/timed-out helpers retain the selected plain frame; cancellation still prevents publication.

The decorated pixels are stored in the existing shared cache, so other file managers see the same border. The sampling/style version is `3`; older Luciole video cache entries refresh, while foreign entries remain reusable and protected. Native video preview requests skip the shared video cache, generate a clean frame and retain it in the memory cache under the preview purpose. They must not overwrite the browsing thumbnail. Non-native/cache-only previews can only use existing cache content, including any baked-in decoration. This is an application-owned adapter for ffmpegthumbnailer, not a general `.thumbnailer` discovery implementation or an icon-theme overlay.

See [PACKAGING.md](../../PACKAGING.md#runtime-integration-and-helpers) for runtime helper dependencies.

## File type detection

Directory listings and recursive filename search request GIO’s `standard::content-type` and `standard::fast-content-type` in their existing cancellable asynchronous batches. Worker-backed single-file details query both attributes too. The shared reader in [file_metadata.cpp](../../src/fs/file_metadata.cpp) prefers a valid regular type and uses the filename-only fast type when the provider omits or returns an invalid regular attribute. A valid `application/octet-stream` result remains authoritative. GIO can inspect content when a filename is insufficient, so extensionless text, dotfiles such as `.bash_history` and extensionless images no longer depend on filename guesses alone.

The resulting DirectoryEntry type drives icons, list type labels, preview selection and the Properties MIME field. File-tooltip details use the same provider policy through the worker query. Do not add filename-specific MIME overrides or move queries into layout/render callbacks. Retain no-follow-symlink flags; regular and special file handling belongs to GIO. This uses existing GIO and shared MIME data, with no decoder or packaging dependency changes.
