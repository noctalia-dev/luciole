# Architecture and ownership

## Dialog lifetime

[PageContext](../../src/app/page/page_context.h) chooses each popup's dismissal through `PopupDismiss`. Menus, popovers and dialogs opened with `OutsideClick` keep normal Wayland grabs and outside-click dismissal. Dialogs opened with `Explicit` (the default for forms) retain their scene, focus and drafts across application-window focus changes, using the existing popup transport without an explicit grab. [BrowserPage](../../src/app/page/browser_page.cpp) consumes dialog-background clicks, restores its text-input context on focus return, and keeps all explicit teardown in ActivePopup. Dialog dropdowns are grabbing child popups of the dialog. KWin and Hyprland move keyboard focus to a grabbing popup, so the parent window's focus loss is not a reason to close the dropdown; the compositor dismisses it when focus moves to another client, and that dismissal is always honored. This is application policy, not a change to the mirrored rendering library.

[WorkspaceApplication](../../src/app/workspace_application.cpp) dims the parent client area behind modal dialogs using one shared Noctalia Box per window. The backdrop uses the palette's Scrim role at half opacity, covers all window content including split panes, and has no input target. Dialogs remain on their own child surfaces above it. [BrowserPage](../../src/app/page/browser_page.cpp) uses the existing Explicit dismissal policy to identify modal dialogs. Quick preview, an outside-click dialog, is dimmed too; other outside-click dialogs such as shortcut help retain an undimmed parent alongside menus and popovers. The existing popup layout/teardown drives backdrop visibility and resizing.

## Module boundaries

[meson.build](../../meson.build) assembles the local Noctalia library and Luciole-owned static modules. [CONTRIBUTING.md](../../CONTRIBUTING.md#module-layering) defines the allowed dependencies. Public domain APIs use `Location`, typed metadata and `CancelToken`; UI callers do not operate directly on GIO file objects.

| Area | Responsibility |
| --- | --- |
| `lib/` | Mirrored renderer, text, scene/input, shared controls, generic Wayland transport and image texture residency |
| `src/model/` | Plain browsing/thumbnail options and shared domain types |
| `src/fs/` | URI-backed locations, filesystem queries, directory sessions, errors and anchored local persistence |
| `src/config/` | Validated settings, GUI overrides, shared bookmarks and private layout/window state |
| `src/browser/` | Published directory model, controllers, selection, history, Miller chains and tab/job routing |
| `src/operations/` | Worker-backed file jobs, conflicts, per-item outcomes and archive services |
| `src/imaging/`, `src/system/`, `src/thumbnails/` | Decoders, artwork resolution, generation providers, metadata and disk cache |
| `src/platform/`, `src/clipboard/` | Luciole-owned desktop launching, decoration, clipboard and native drop transport |
| `src/ui/` | Luciole-specific views and compositions of actual Noctalia controls |
| `src/app/`, `src/event_loop/` | Application ownership, page orchestration, platform polling and GLib integration |

The application uses direct Wayland and OpenGL ES with Pango/Cairo. GdkPixbuf/Glycin supplies image decoding, not a widget layer. Builds consume the checked-in mirror; a sibling checkout and the Noctalia shell are not runtime/build requirements. Generic library changes go upstream before reviewed updates are copied back into Luciole.

## Network discovery

Network is a built-in destination in [PinService](../../src/browser/places.cpp), with its order saved in the private Places layout. Both the normal sidebar and its optional folder tree filter it through `browser.show_network`, independently of the drive-row preference, retaining underlying layout indices for drag/drop. Missing Network slots are appended to existing layouts. Network is not automatically exported to GTK bookmarks, and an explicit existing Network pin is deduplicated. Its row supports local reordering but never file transfer; hiding it leaves direct network addresses and existing views usable. This follows [Thunar's hideable Network shortcut](https://github.com/xfce-mirror/thunar/blob/master/thunar/thunar-shortcuts-model.c), with ordering adapted to Luciole's unified Places list. Creating its row/root only constructs a Location and model entry; it does not enumerate, mount or monitor the destination. No application-wide availability subscription, discovery timer or startup network enumeration is retained.

Opening `network:///` or explicitly expanding its tree root starts [NetworkListing](../../src/fs/network_listing.h) through the cancellable DirectorySession. The composite source uses a shared, on-demand [WsDiscovery](../../src/fs/ws_discovery.h) client and a bounded child session at `dns-sd://local/`. It never enumerates GVfs's aggregate Network or WSDD root, so neither backend nor an external WSD helper is needed. Only SMB-target DNS-SD shortcuts are merged. Real server locations remain `smb://` URIs; discovery labels and stable logical IDs are separate from operation locations. Direct addresses and pinned shares remain independent of discovery. GVfs retains ownership of share browsing, mount/login, file operations and its optional DNS-SD service. Metadata HTTP requests use system libcurl on workers, connecting to the numeric discovery sender with the advertised Host preserved. Proxies and redirects are disabled; HTTP/HTTPS, TLS verification, bounded headers/body, an eight-second deadline and cancellation remain enforced. The worker polls at most 50 ms before rechecking cancellation.

Interface enumeration, monitor construction, UDP sockets, packet/XML parsing, metadata target validation and HTTP/XML metadata requests run on cancellable workers. The main context receives a bounded mailbox and coalesces publications. The last open Network listing releases the shared client without joining a worker. Refresh and network changes cancel the previous generation. The client probes both discovery dialects on multicast-capable IPv4/link-local IPv6 interfaces, correlates bounded Probe/Resolve replies, listens for Hello/Bye, and expires stale records. A ten-second initial window and periodic probes apply only while Network is open. [Wire helpers](../../src/fs/ws_discovery_protocol.h) parse namespaces rather than XML prefixes, reject DTDs and bound document size/depth/nodes. Metadata connects only to the numeric UDP sender, disables proxies/redirects, bounds response bytes/concurrency and cancels at an absolute deadline. A missing name leaves a usable numeric server destination. No background startup scan, server-share enumeration, persisted credentials, Qt/KDE stack, copied third-party discovery implementation or library-mirror change is introduced.

DirectorySession retains a shortcut's validated `standard::target-uri` in its optional shared EntryExtra. The shortcut's own location remains its listing/operation identity; navigation uses the target in activation, new tabs and Miller columns. Missing, invalid and self-referential targets do not launch a default handler. Discovery-directory monitors are created on a cancellable worker, connected on the main context and followed by a refresh to cover the read-to-watch handoff. Navigation and destruction reject late monitor completions. Other remote-folder monitoring retains its existing explicit limitation. Explicit browsing still uses the normal NotMounted mount flow; passive tree enumeration never asks for credentials.

## Mounting browsing locations

[BrowserController](../../src/browser/browser_mount.cpp) handles a distinct NotMounted failure from its passive DirectorySession by starting one asynchronous enclosing-volume mount for that explicit browsing attempt. [LocationMount](../../src/fs/location_mount.h) owns cancellable enclosing-volume and mountable-item GIO requests and [MountInteraction](../../src/fs/mount_interaction.h) bridges password/question signals into typed pending requests. A successful mount, including a concurrent AlreadyMounted result, refreshes the original session without adding another history visit. Other file/network errors are not blanket mount triggers. Explicit refresh permits another attempt; navigation, Stop and controller destruction cancel and invalidate the old completion. Search/tree scanners do not start interactive mounts. Mountable entries, including SMB server shares, use GIO mount_mountable and navigate to its returned folder rather than launching an application or trying to enumerate a mountable object. Only NotSupported falls back to enclosing-volume mounting. The resolved folder replaces the pending history location rather than adding another visit.

[MountController](../../src/app/page/mount_controller.cpp) presents pending requests from the active browsing context through [MountDialog](../../src/ui/dialogs/mount_dialog.h), composed with actual Noctalia controls on the page's explicit-dismiss popup. Request IDs and browser context IDs reject obsolete answers. Background tabs wait for their own presenter; closing a login dialog aborts that request. Default GMountOperation password/question handlers are stopped so their unhandled idle reply cannot race a human response. Provider-supplied messages are bounded, repaired to UTF-8 and displayed literally. Question lists are bounded to sixteen choices. Password-only requests retain the provider's user/domain; guest access requires the provider's explicit anonymous capability. Unknown authentication flags abort with an explicit unsupported-method error.

Credentials stay in the live operation/dialog and go to GIO, with session-only saving when supported. Luciole does not write them into configuration, bookmarks or a password store. The operation and its secret are released/cleared on completion or cancellation. A cancelled or superseded operation keeps only the references required for its eventual async finish. Missing backends remain explicit failures. This is application-owned desktop interaction; no shared Noctalia library, mount helper process or new dependency is introduced. Device unlock/process-blocked prompts and full provider coverage remain unfinished. [Nautilus](https://github.com/GNOME/nautilus/blob/main/src/nautilus-mime-actions.c) likewise requests an enclosing mount, handles authentication and retries access; Luciole supplies its own controls instead of GtkMountOperation.

For an unsupported remote directory-open error, DirectorySession checks GIO's advertised URI schemes on a worker. An absent scheme receives backend/session setup guidance containing only the scheme, without echoing address credentials. An advertised protocol retains its provider's error, and native/Trash errors retain their existing handling. Request identity rejects diagnostic replies after navigation, cancellation or destruction. Only NotMounted starts mounting; an unsupported protocol never triggers an authentication retry.

## System automounts

[SystemMountMonitor](../../src/fs/system_mount_monitor.h) reads network entries from fstab, loaded systemd mount/automount pairs for the same NFS and SMB share types, and the kernel mount table. It watches GIO and systemd for changes without opening mount paths. If a systemd query times out after two seconds, the monitor keeps its last snapshot. It remembers an unloaded pair while its unit files exist.

[DriveMonitor](../../src/fs/drive_monitor.h) keys sidebar entries by target URI and honors `x-gvfs-show`, `x-gvfs-hide`, and `x-gvfs-name`. An idle automount keeps its row. Disk-usage polling and directory watches would keep the share active, so the user refreshes it explicitly. Ordinary user-mountable fstab entries still use `mount`.

Opening a configured automount verifies the mounted filesystem before browsing. An unavailable share reports an error.

## Windows, tabs and pages

[WorkspaceApplication](../../src/app/workspace_application.h) owns native windows, the workspace, application-wide preferences and caches, and the [OperationHub](../../src/app/operation_hub.h). The `single_window` preference keeps one browsing window: forwarded launches and FileManager1 requests add tabs to `browsingWindow()` (the focused live browser window, else the first) instead of calling `newWindow()`, New Window degrades to a tab, and Detach is skipped. File chooser windows are unaffected. [TabWorkspace](../../src/browser/tab_workspace.h) represents logical tabs and optional splits. A native host supplies the visible toolbar/sidebar and mounts the active page roots. `TabWorkspace::addTab()` accepts explicit activation intent; background insertion retains the selected tab and its full split layout/focused page, while the first tab of an empty window is necessarily active. Folder-opening workspace commands follow the shared `switch_to_new_tab` preference; explicit New Tab and one-off background commands carry separate intent. Hidden pages initialize their directory controllers normally without mounting their scene or taking focus. Background loading and errors do not select a tab. Middle-clicking a folder in an inactive split pane leaves the original pane focused when opening in the background.

GIO's volume monitor starts its monitor services synchronously, so [DriveMonitor](../../src/fs/drive_monitor.h) starts after a window's first frame; device rows appear through the usual change notification just after. Its constructor still makes the serialized first mount-table query that GIO needs before worker threads query filesystems. The process pins glibc's mmap threshold at 128 KiB, so large listing arrays are mapped separately and return to the system when freed.

[BrowserPage](../../src/app/page/browser_page.h) orchestrates feature controllers rather than implementing file jobs or decoder work. Each page has its own browse controller, selection, history, query and viewport. Its [MillerColumns](../../src/browser/miller_columns.h) chain owns additional lazy controllers within the same page. The focused controller supplies action and preview targets. Offscreen/retired branches release resources; at most 16 live columns remain while deeper navigation retires old ancestors.

Successful Parent Folder navigation returns keyboard focus to the active page's file view immediately; the existing pending-target mechanism selects and reveals the departed folder when the parent listing arrives. The shared focus helper prevents an inactive pane from taking the window's focus. Existing Columns ancestor navigation retains its own focus handoff. [Nautilus's parent-navigation selection calculation](https://github.com/GNOME/nautilus/blob/main/src/nautilus-window-slot.c) also selects the departed folder when navigating to an ancestor. This is a source comparison, without a live Nautilus check.

Page visibility does not confer ownership of running file jobs. Accepted Follow-scope jobs can move to another page when a tab closes; page-scoped preparation is cancelled. The OperationHub also owns bounded recent activity reports and one in-memory native rename Undo/Redo record across pages and windows. Its job ownership/activity adapter is compiled as the internal `luciole-app-jobs` static library so headless tests exercise the actual application lifecycle without UI wiring. See [file jobs](file-jobs.md). Optional last-window tab restoration is persisted in the versioned state store and consumed after a successful restore.

### Adaptive sidebar

[AdaptiveSidebar](../../src/model/adaptive_sidebar.h) separates the saved docked visibility from temporary drawer state. Below 760 logical pixels, the active page presents its Places subtree as a drawer; entering compact mode closes that drawer, and widening restores the saved preference. Compact toggles never write preferences. SidebarController retains the user's width and the reusable Places tree across page switches, while temporary drawers close when the window changes its active page.

[sidebar_drawer.cpp](../../src/app/page/sidebar_drawer.cpp) owns the toolbar toggle, bounded slide animation, scrim, focus and keyboard scope. Animation callbacks belong to the controller and are cancelled on destruction. Panel position and scrim opacity interpolate independently: automatic resizing slides the docked sidebar away without introducing a dimming flash; explicit drawer opening and dismissal fade the scrim. Wide visibility changes also animate the reserved content width. Escape clears the toggle selection and returns focus to the file view. Tab stays within the open drawer. The existing animation manager supplies timing and motion policy; no shared-library edits are needed.

The host arranges the layer below the toolbar and routes covered pointer and external-drop events to the active page before considering panes underneath it. A clipping container keeps hit testing enabled for its children. The sidebar panel sits above a separate outside-click/scroll blocker; file-view click, middle-click, tooltip, column-header and drop probes cannot target obscured contents. Existing Places callbacks, lazy tree sessions, menus, pin reordering and supported folder transfers remain authoritative. Layout owns geometry and visibility; render callbacks do not mutate the scene.

This follows [Nautilus' collapsed OverlaySplitView](https://github.com/GNOME/nautilus/blob/main/src/resources/ui/nautilus-window.blp) and [libadwaita's overlay-sidebar behavior](https://gnome.pages.gitlab.gnome.org/libadwaita/doc/main/class.OverlaySplitView.html), using Noctalia controls and Luciole's existing width preference. Luciole uses a 760-pixel breakpoint and retains the docked preference independently. The comparison is based on primary sources, not a live Nautilus test. There is no new dependency, installed asset, settings key or state schema.

### FileChooser portal windows

`luciole --file-chooser-service` is a separate D-Bus activated process that owns `org.freedesktop.impl.portal.desktop.luciole` and nothing else: no single-instance name and no FileManager1. [FileChooserService](../../src/platform/file_chooser_portal.h) parses each OpenFile, SaveFile or SaveFiles call into a typed request and hands it, with a [FileChooserCall](../../src/platform/file_chooser_portal.h) that owns the pending reply and its exported Request object, to `WorkspaceApplication::choose()`. The call answers exactly once: success, cancellation, or 2 for a frontend Close, a failure or a call dropped unanswered. Close is accepted only from the original caller. Open and Save inspect symlinks and save destinations asynchronously on workers; a selection, name or folder change invalidates pending checks, and Save asks again if the set of existing destinations changes before confirmation.

A chooser window is an ordinary host with a single ordinary BrowserPage in chooser mode, plus a [FileChooserSession](../../src/app/file_chooser_session.h) that owns the request, its filters and choices, and the footer. Its Wayland app ID is `dev.noctalia.luciole-chooser`, distinct from browsing windows' `dev.noctalia.luciole`, so compositor rules can target chooser windows. A NoDisplay desktop entry with that ID reuses the Luciole icon, so shells still resolve the chooser's name and icon. Chooser hosts never save or restore the browsing session, ignore workspace commands and external drops, hide the tab strip and never use Miller columns. Their view mode, sorting, hidden-file visibility, zoom and preview visibility come from and save to the separate `chooser_*` settings, so a chooser's layout never changes the browser's. The requested `current_folder` or `current_file` always decides the start folder; without one, `chooser_start_folder = "last"` reopens the folder recorded in `state.toml` when the previous pick was accepted, written by a worker as a last-writer-wins section, and otherwise the chooser opens Home. In chooser mode the page never launches files: Open goes to the session, which decides through [chooser_policy](../../src/browser/chooser_policy.h) whether to enter a folder, accept or explain why not. The action registry disables every action outside a fixed list of browsing and selection actions plus New Folder, so menus, shortcuts and controllers cannot start any other file job. A toolbar button shown only in chooser windows offers New Folder, which creates the folder in the current location and selects it. Portal filters hide non-matching files through a `DirectoryModel` entry filter. Links stay visible because listings report them without their target's kind, and the policy resolves the selected ones. A `wayland:` parent handle is imported through xdg-foreign, and the window is made modal through xdg-dialog when the request asks for it.

Saving chooses destinations and writes nothing. SaveFile adds a name field to the footer: it takes keyboard focus with the stem selected, its keys bypass the page's shortcuts, selecting a file or a link to one copies its name into it (a link's target is read on a worker, since it may sit on a slow mount), and a name that is an existing folder enters it. SaveFiles shows folders only and saves the application's names into the current folder. When a destination exists, the first Save only asks, and saving the same destinations again replaces them; navigation or a name edit withdraws the question.

## Asynchronous publication

[DirectorySession](../../src/fs/directory_session.h) enumerates asynchronously and publishes typed snapshots. Ordinary local name-sorted folders above 512 entries (and mounted network filesystems above 64 entries when `readdir` supplies dirent kinds) use an immutable browse catalogue: raw names share one NUL-separated buffer, display-name exceptions remain separate, and compact rows retain IDs, kinds, hidden/link bits and opaque dirent inode hints. The hints validate directory-entry continuity; they never replace GIO's actual provider identities. Only visible/overscan rows and explicit consumers request detailed facts. A cancellable worker queries GIO in batches of at most 128 rows; at most 1024 detailed rows remain in the current working set. Owner, group, permissions and accessed/created time are requested only for enabled extra columns or explicit consumers. A queried-field mask distinguishes pending optional facts from completed unknown values. Small folders, metadata sorts, selections above 512 entries and expandable trees retain the eager path. Provider, Trash and unsupported local filesystems retain their existing GIO path. Mounted network filesystems omit per-child `access::can-read`/`write`/`execute` and content-sniffed `standard::content-type` during GIO enumeration and catalogue fact batches, keeping `standard::fast-content-type` and parent-level rename/delete/trash checks so listings avoid per-file `ACCESS` and `OPEN`/`READ` network RPCs without deferring access checks to the main thread.

Catalogue snapshots share the immutable names/kinds, and each metadata publication replaces its sparse immutable fact overlay. Retained snapshots and copied operation entries keep their original values. Model name/filter/locale keys and projection indexes survive fact-only publications, avoiding another whole-folder sort. Plain catalogue views do not construct rich entries for every row. A row batch rechecks requested dirent hints and the original parent identity before publishing facts; replacements retire IDs and restart the scan, while unavailable checks disable actions. This validation enumerates directory names without statting every file and handles child mount points without mistaking their dirent hints for actual inode identities.

File actions await required facts and then use the existing capability, context, URI, identity and revision checks. Selection totals show pending sizes explicitly; large selections and metadata sorts prepare complete entries. History resolves only captured references. Duplicate/Miller transitions retain their own captured source payload and cancellable identity query, so closing the original controller cannot lose pending selection restoration. Navigation or destruction cancels that destination's query. Source ownership, rather than a borrowed controller pointer, governs its lifetime.

Outside the catalogue path, Local folders on local filesystems are listed by [native_listing](../../src/fs/native_listing.h) on a worker with `readdir` and one `statx` per entry; every fact equals what GIO's local backend reports, which the session test checks entry by entry. Content types come from `g_content_type_guess`. Names it is uncertain about publish with that guess and `contentTypesPending` set; a second worker pass then reads them through GIO, exactly as GIO sniffs, and publishes the sniffed types and icons after 100 ms, then at doubling intervals up to 1.6 s. A rescan keeps the sniffed type of a file whose size, modification and change times are unchanged. Access read/write/execute are deferred: [entryAccess](../../src/fs/entry_access.h) answers them with `access(2)` for the rows and targets that need them; rename, delete and trash stay in the entry. Mounted network filesystems above 64 entries may use the browse catalogue path (whose row facts still come from GIO on a worker); otherwise network and FUSE filesystems, entries that cannot be inspected and every other provider keep GIO's enumeration. [DirectoryEntries](../../src/fs/directory_entries.h) separates the snapshot header from shared immutable payload blocks. A completed session moves its private entry vector into a published block; controller and model copies retain that generation rather than duplicating the entries. An entry stores its name and a shared folder; `location()` builds the child location on demand, and only entries outside a listed folder hold a whole location. Local entity tags and file identities are numbers whose text forms are rebuilt exactly; display names that differ from the name, provider tags and identities, search context and Trash facts are shared side data. MIME types and owner/group names are interned [InternedText](../../src/fs/interned_text.h) and change revisions are two integers, so a common entry carries no per-entry copies of them. The session's name-to-ID table indexes the published entries instead of copying their names. Operation names and escaped URIs remain separate from display text; sorting or Unicode search must not rewrite operation identities.

Native listings, catalogues included, never follow symlinks. After publication, a worker pass follows each link with `statx` and republishes once it knows which links lead to folders, so Folders First can group them and they show the folder icon in place of the generic link icon; a catalogue records them in an overlay beside its shared names and kinds, and detailed facts keep that kind. Until the pass returns, a link keeps the kind the previous scan of the same folder found, or sorts with the files. Following a link can block without end on an unresponsive network or FUSE mount, and cancellation cannot interrupt it, so the link passes of every session share two workers: hung targets hold at most two GIO pool threads, later passes wait for a free worker (at most 64; beyond that the oldest is dropped), and a pass from a replaced or cancelled scan is discarded when it returns.

An icon pass shares those workers. On a local, non-network filesystem it reads each folder's custom icon with [customFolderIcon](../../src/fs/custom_icons.h): GIO's `metadata::custom-icon`, then `metadata::custom-icon-name`, then `Icon=` in the folder's `.directory`. Links get their icons from the link pass instead: once a link's target has answered, it calls `linkTargetIcon`, which gives a custom icon set on the link or on its target folder, the plain folder icon, or the icon of the target's content type. A link to a hung mount therefore holds only the worker its link pass already holds. The icon pass works in slices of at most 4096 folders and 100 ms, doubling up to 1.6 s. After each slice it publishes what it found and queues again behind the other passes, so a folder with thousands of subfolders does not keep a worker from them. The session keeps the results by name as overrides of the listing's icons. It applies them, only to folders and links, to the published entries, and in a catalogue to each row's facts as they arrive. A rescan keeps the previous overrides until the pass that reads them finishes, then drops those it did not find again. A dangling link keeps the link icon.

Change notifications rescan after 80 ms, or after twice the previous scan's duration when that is longer (at most 2 s). A scan that finishes after further changes is discarded and rescheduled, unless nothing was published for a second: then the session publishes it, keeping the IDs monitor events maintained meanwhile, and rescans. A folder that changes continuously therefore still updates about once a second. Publishing or replacing a listing of 10,000 entries or more schedules a low-priority `malloc_trim`.

[DirectoryTree](../../src/browser/directory_tree.h) shares its root and child payloads. Expanded rows use an index projection that retains the underlying blocks, including after a source session is collapsed or replaced. A tree-owned identity registry supplies child IDs when entries are constructed; URI/identity checks preserve surviving IDs and independent occurrences keep separate IDs. Unexpanded trees share the root directly. [RecursiveSearch](../../src/fs/recursive_search.h) publishes immutable matching batches and concatenates block references. New collections retain payload blocks directly, without retaining chains of older projection tables. Search notification cadence and model sorting still have their existing costs.

Published entries expose no mutable access. Refresh invalidation that changes access facts creates a replacement payload once for that invalidated generation; retained snapshots keep their original facts. A completed scan replaces that payload, and late callbacks remain guarded by session generation/cancellation. Views borrow entries only until the next model mutation; consumers needing a longer lifetime must retain the collection or copy the required operation facts. Sharing does not change metadata completeness, raw names, selection or job revalidation.

The model caches name/filter keys by stable ID when the display name and containing location remain unchanged. Presentations live in a vector indexed like the snapshot's entries and hold offsets into one key buffer; an open-addressing ID index and a per-entry row index replace per-ID hash nodes, and a filter key is stored only when folding changes the display name. Type, Owner, Group and Location collation keys are prepared only when selected, before sorting, and shared for repeated values or parent URIs. One alternate-field pool is retained per snapshot; refreshed metadata invalidates it. Pointers into that private pool survive rehash and never escape the model. Raw operation names, locations and provider metadata remain authoritative.

Selections, focus and anchors use stable entry IDs, not row indices. Refresh preserves surviving identities; deletion/replacement retires them. Controllers reject old generations. A pointer release must not activate a different entry after a virtual row is rebound.

When a completed same-location snapshot removes the cursor's ID, DirectoryModel searches the previous visible order forward and then backward for a surviving visible ID. Remaining selected items receive cursor priority; when the selected cursor was the final selected item removed, its successor becomes selected and the range anchor follows. A cursor without selection stays unselected. Newly inserted or replacement IDs cannot become fallback targets, and an empty expanded branch cannot move selection into another branch. The old order is retained only for an actual removed cursor, keeping ordinary metadata publications on their existing path. Filtering, navigation, cancellation, partial/error listings and fresh incremental loading do not trigger this continuation. [Nautilus's display_pending_files](https://github.com/GNOME/nautilus/blob/main/src/nautilus-files-view.c) similarly preserves a nearby cursor when processing removals loses view focus; Luciole uses surviving identities rather than a row-number fallback. This is a primary-source comparison, without a live Nautilus check.

The main loop integrates the default GLib context through [GlibPollSource](../../src/event_loop/glib_poll_source.h), alongside the shared Wayland and deferred-call sources. Workers perform filesystem traversal, decoding, provider work and configuration reads/writes. Completion callbacks verify cancellation, captured context and owner lifetime, then request Update/Layout/Redraw. Rendering must not perform I/O or rebuild the scene.

Relevant regressions include [directory sessions](../../tests/directory_session_test.cpp), [models](../../tests/directory_model_test.cpp), [Miller columns](../../tests/miller_columns_test.cpp), [tab workspace](../../tests/tab_workspace_test.cpp), [job routing](../../tests/job_routing_test.cpp) and [input lifetime](../../tests/input_lifetime_test.cpp). GUI ownership and compositor behavior also need isolated real-window checks; headless contracts alone do not establish them.
