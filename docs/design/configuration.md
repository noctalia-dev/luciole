# Configuration and persistence

The [user configuration guide](../user/configuration.md) owns the preference reference. The implementation is [settings.h](../../src/config/settings.h), [settings.cpp](../../src/config/settings.cpp) and [ViewPreferenceWriter](../../src/config/view_preference_writer.h).

## Ownership and reload

Built-in defaults are overlaid by the optional base `config.toml`, then writable GUI `settings.toml`. GUI edits never modify the base. Canonical names have one spelling. Runtime loading warns about unknown root/browser keys and decodes recognized preferences normally. The validation CLI remains strict about unknown keys and checks one required file, with no adjacent overrides and no compositor initialization. Wrong types, unsupported known values, incompatible schema versions and malformed TOML still fail. Schema version is integer 1 when supplied. This policy applies to configuration files, not the separate Places state schema.

The worker serializes typed edits and reload requests, coalescing pending edits per preference. Saves reread and validate actual persisted inputs before merging only the requested keys. The override document retains unknown values, arrays and tables while known preference fields are replaced or removed; comments and original formatting are not retained on a changed save. No-op saves preserve the exact bytes. Removing an override restores inheritance. Reset removes only recognized preferences, preserving unknown values for another application version. An invalid reload keeps the last valid snapshot; failed saves reload actual persisted state. Publish only after pending edits/reloads drain.

File monitors follow canonical files, existing path components and resolved declarative targets. Coalesced events trigger worker reads; the read after watch installation closes the read/install gap. Callbacks publish during Update. Only relevant global changes should replace a live preference; an unrelated reload must not reset the current visit's view/zoom/history state. Ordinary close drains pending preference saves.

Explicit sort changes from menus, list headings and the open Settings dialog share BrowserPage's sort application path. They preserve model selection IDs and request the beginning of the new order. Layout consumes that request after preference notifications and view switches, clearing any intervening captured scroll anchor or pending history viewport before arranging the virtualized cells. Ordinary reloads and unrelated preference changes retain their existing viewport behavior.

## Settings layout

[SettingsController](../../src/app/page/settings_controller.cpp) retains the preferred 880-pixel dialog width independently of the opening window size. The common popup layout in [BrowserPage](../../src/app/page/browser_page.cpp) calls `layoutDialog()` before measuring Settings on each requested layout. It reapplies the parent-constrained height up to 640 pixels and the compact navigation breakpoint. Parent configuration already requests popup layout and recenters the dialog. Resize the existing view so its category, scroll state, focus and drafts survive; dismiss an open select dropdown when its anchor geometry changes. Do not persist the temporarily constrained popup dimensions as its preferred size.

## Filename presentation

`browser.filename_truncation` accepts `middle` (default) and `end`. Settings → Views → Long Filenames uses the existing typed preference and Select control. BrowsePresentation carries the value to every pane; FileRow and FileTile apply the Label ellipsis mode on bind, including recycled List rows, expanded folders, Miller columns and Grid tiles. Grid keeps its two-line wrapping and applies the preference to overflow. Parent labels, metadata columns, Places, tooltips and raw operation names retain their existing behavior. Sorting, selection and metadata loading are independent of the preference.

Plain single-line Middle text uses the shared renderer's compact layout. Pango stretches its synthetic ellipsis run after removing whole grapheme clusters; the renderer subtracts that excess advance from the layout budget and asks Pango to lay out again. It uses public APIs without rewriting filenames or modifying Pango-owned glyph data. Actual spaces remain text. Start/End, markup and multiline layouts retain normal Pango behavior. The correction lives upstream in Noctalia and is mirrored into Luciole.

## Typing and query scope

`browser.typing_mode` accepts `search` (default), `filter` and `typeahead`. The Settings General page uses the existing Select control for all three. Search and filter typing, including input-method commits, use the same toolbar field; current-folder mode updates its placeholder and tooltip. Explicit field entry and Ctrl+F use that same scope. Typeahead retains recursive explicit search. Preference changes update every existing pane and Miller controller. The field's leading glyph button, or the Search shortcut while the field has focus, flips the scope of one pane through `PageContext::setSearchRecursive` without saving it; new panes start from the preference.

[BrowserController](../../src/browser/browser_controller.cpp) owns the scope. Recursive queries keep their 175 ms debounce and worker traversal. Local edits project the current DirectorySession listing through DirectoryModel’s folded literal name filter, without starting traversal or re-reading the folder on each keystroke. Session monitor updates remain visible under the filter; refresh, navigation history and duplication retain the scope. Filtering temporarily projects only the root listing when expandable list folders are enabled. Mode changes cancel pending recursive work before publishing the appropriate source. Miller child and ancestor controllers inherit the source scope.

## Drop action

`browser.drop_action` accepts `menu` (default), `copy` and `move`. Settings → General → When Dropping Files uses the typed preference and Select control. [DragDropController](../../src/app/page/drag_drop_controller.cpp) resolves the same value for internal drags, external drop targets and the drag cursor. Ctrl, Shift and Alt keep priority over the preference, and Trash, items from Trash and non-native folders keep their existing fixed behavior. `menu` sets `DragAction::Ask`, so [TransferController](../../src/app/page/transfer_controller.cpp) shows a drop action context menu anchored at the drop point through [MenuController](../../src/app/page/menu_controller.cpp), offering Copy Here, Move Here, Create Link Here, Extract Here and Move into New Folder… with one shared cancellation path.

## Context menu icons

`browser.context_menu_icons` defaults to `true` and appears under Settings → Appearance. Action glyph names live beside each action in [ActionRegistry](../../src/browser/action_registry.cpp), and sort actions reuse `sortFieldGlyph()` from [DirectoryOptions](../../src/model/directory_options.h) so the Sort and Columns menus agree; one-off menus set the same `ContextMenuControlEntry::glyph` field. [MenuController](../../src/app/page/menu_controller.cpp) and [SubmenuController](../../src/app/page/submenu_controller.cpp) apply the preference with `applyContextMenuIconPreference()` before publishing entries. Disabling it removes the reserved leading column without changing entry ids, checkmarks, shortcuts or submenu behavior.

## Atomic writes

[atomic_file.cpp](../../src/fs/atomic_file.cpp) implements anchored local transactions. Cooperating writers use a persistent advisory lock. Preserve that lock across ordinary cleanup; unlinking it can split writer coordination. New private directories use 0700 and data/temporary/lock files use 0600.

Writes use an exclusive neighboring temporary, file flush, destination revision recheck, atomic publication and parent-directory flush. First creation must not replace an unexpected destination. Reject unsafe sidecar targets, including symlink/hard-link, foreign-owned, special and read-only files. Declarative base symlinks remain readable under the loader's separate rules.

Outcomes distinguish unchanged, not committed, committed but directory synchronization failed, and durable. Report visible-but-not-durable commits accurately. Cleanup removes only the transaction's own temporary. This protects cooperating writers and ordinary races; it does not promise atomic exclusion of an uncooperative same-user writer between a final check and rename.

## State and caches

[SharedBookmarks](../../src/config/shared_bookmarks.h) owns the GTK-compatible `$XDG_CONFIG_HOME/gtk-3.0/bookmarks` document. [Nautilus](https://github.com/GNOME/nautilus/blob/main/src/nautilus-bookmark-list.c), [Nemo](https://github.com/linuxmint/nemo/blob/master/src/nemo-bookmark-list.c) and [GTK](https://github.com/GNOME/gtk/blob/main/gtk/gtkbookmarksmanager.c) use this URI-plus-optional-label format; GTK 4 continues using the gtk-3.0 path. The older HOME/.gtk-bookmarks is a read fallback until a modern document is seen. User bookmarks are authoritative there, without importing old Luciole pins. Valid native/remote URIs and labels are read without probing destination availability. Display is deduplicated; opaque, unsafe, duplicate and overflow records remain in the document when unrelated bookmarks are edited. Credentials are never copied into Luciole state or shown in bookmark labels.

[PinService](../../src/browser/places.h) serializes worker reads/writes and projects shared user bookmarks into the built-in Places layout. [StateStore](../../src/config/state_store.h) retains that layout and optional last-window tab state with separate revisions. Cached custom rows are placement slots only: shared order/labels replace them and deleted shared rows cannot be resurrected from state. Built-in rows are not seeded into the shared file; an explicitly shared built-in URI is shown once and its label is honored, except protected Trash. The shared file supports 256 displayed bookmarks; layout storage allows those plus at most eleven built-ins. Overflow records remain untouched. No state schema or migration marker is added.

[FolderViewService](../../src/browser/folder_views.h) owns per-folder sort and view mode for the whole application. It reads and writes [FolderViewStore](../../src/config/folder_view_store.h) (`folder_views.toml`) on a serial worker and answers lookups from memory. `BrowserController` keeps the default sort and view mode apart from the effective ones and applies the current folder's settings in `loadVisit()`. It does that only while `browser.remember_folder_views` is on; with it off, `loadVisit()` leaves the sort and view mode unchanged. Every change, load or enable switch runs the service's changed callback. `WorkspaceApplication` passes that to each page, whose [FolderViewController](../../src/app/page/folder_view_controller.h) re-applies the folder settings to the page's controller and Miller columns. The same controller decides whether a sort or view change goes to the current folder or to the defaults. Column view stays a window-wide default and ignores folder view modes. `BrowserPage::options()` seeds new pages with the defaults, not the current folder's settings. File picker pages get no service, so they neither read nor write folder settings and keep their `chooser_*` sort and view mode.

Bookmark icon overrides are private state attached to the cached bookmark row by URI. `combine()` carries them onto matching shared rows while shared labels and ordering remain authoritative. The GTK file writer compares and preserves only URI and label, so an icon-only edit does not rewrite shared bookmark contents.

Directory watches cover the shared/legacy files, parent replacement, missing directories and resolved symlink targets. A 50 ms debounce coalesces reloads; changes arriving during worker I/O request another serial reload. New target watches trigger a re-read to cover handoff. Shutdown disconnects watches and cancels the debounce, while already queued writes finish without UI callbacks. Read errors preserve displayed rows and disable edits until reload succeeds. Session-save errors remain independent.

Shared reads are bounded to 256 KiB and require a stable regular file; managed symlinks can be read. Writes reuse the checked atomic writer, require an owned writable regular file without links, retain untouched URI/label bytes and compare the document before replacement. Stale UI proposals are rejected after reloading both sources. The shared commit precedes local layout persistence; a layout failure reports an error without pretending to roll back the shared commit. There is no transaction across both files, or atomic exclusion of an uncooperative same-user writer in the final check-to-rename window. Do not conflate settings, Places/session state, future operation journals and regenerable thumbnails. Credentials do not belong in configuration, state, URI history or cache identities.

The shared thumbnail cache is regenerable. A future operation journal has different ordering/recovery requirements; cache persistence is not an implementation of crash-safe file-job recovery.
